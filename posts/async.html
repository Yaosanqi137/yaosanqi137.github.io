深入理解 JavaScript 异步模型

2026-10-28 · JavaScript · 8 分钟

JavaScript 是单线程的，却能处理海量并发请求。这背后的核心是事件循环（Event Loop）。很多异步“坑”都源于对宏任务、微任务、Promise 协作方式理解不清。这篇文章把这套机制一次讲透。

事件循环是唯一的“调度器”

浏览器把可执行的代码分成两类：

  • 宏任务（macrotask）：setTimeout、setInterval、I/O、UI 渲染等。
  • 微任务（microtask）：Promise.then、queueMicrotask、MutationObserver。

事件循环的每一步：执行一个宏任务 → 清空所有微任务 → 渲染 → 再执行下一个宏任务。

一段经典代码

console.log('1');

setTimeout(() => console.log('2'), 0);

Promise.resolve()
  .then(() => console.log('3'))
  .then(() => console.log('4'));

console.log('5');

输出顺序：1 5 3 4 2。

原因：console.log 是同步代码，先执行；两个 Promise.then 是微任务，必须在下一个宏任务（setTimeout）之前清空；所以 3、4 在 2 之前。

为什么微任务优先？

微任务代表“数据已经准备好了”的状态，比如 Promise 的结算。如果让宏任务（如定时器）插队，UI 状态就会撕裂。所以引擎规定：微任务必须在当前宏任务结束后、渲染之前全部清空。

一句话：宏任务决定“何时做”，微任务决定“紧接着做什么”。

常见误区

1. setTimeout(0) 不是立刻执行

它只是把回调排进下一个宏任务队列，期间微任务会先跑完。

2. async/await 是语法糖

await 之后的代码本质是一个微任务，所以它比 setTimeout 更快执行。

3. 死循环会卡死 UI

事件循环只在宏任务之间才检查渲染。一个同步死循环会让整个页面冻结，必须靠 setTimeout 或 requestAnimationFrame 让出控制权。

小结

  • 事件循环 = 宏任务队列 + 微任务队列 + 渲染时机。
  • 微任务永远优先于下一个宏任务。
  • 理解这套模型，异步竞态、状态更新顺序就不再神秘。
