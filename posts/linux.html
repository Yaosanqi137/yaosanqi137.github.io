Linux 进程与线程：一次讲透

2026-10-15 · Linux · 10 分钟

操作系统里的“并发”听起来玄，其实就两样东西：进程和线程。进程是资源分配的单元，线程是 CPU 调度的单元。把这两者分清楚，剩下的都是细节。

进程：独立的地址空间

每个进程都有自己的虚拟地址空间、文件描述符、堆栈。进程之间默认不能直接访问对方的内存，必须通过 IPC（管道、共享内存、消息队列）通信。

线程：共享一切，除了栈

同一进程内的线程共享代码段、数据段、堆、文件描述符，只有栈、寄存器、线程局部存储是独立的。

属性进程线程
地址空间独立共享
创建开销大（fork）小（clone）
崩溃影响互不影响全进程结束
切换成本刷 TLB、换页表仅换栈指针

fork 到底做了什么

int pid = fork();
if (pid < 0) {
    // 创建失败
} else if (pid == 0) {
    // 子进程
} else {
    // 父进程，pid 是子进程 PID
}

现代 Linux 用 COW（Copy-On-Write）：fork 后父子共享物理页，谁修改谁才真正复制。所以 fork 几乎不拷贝数据，非常快。

线程同步：互斥与条件变量

线程共享数据，必然竞争。最基础的工具是 互斥锁（mutex）和条件变量（condvar）：

pthread_mutex_lock(&m);
  // 临界区：读写共享变量
pthread_mutex_unlock(&m);

死锁是经典陷阱：两个线程各持一把锁等对方。解决思路是固定加锁顺序，或改用 trylock + 回退。

调度：CFS 公平队列

Linux 默认调度器是 CFS（完全公平调度），它用红黑树维护“最小虚拟运行时间”的进程，每次把该进程调度到空闲 CPU 上。优先级（nice）影响的是“被调度的频率”，而不是独占。

小结

  • 进程隔离、线程共享，是并发的根本分界。
  • fork + COW 让进程创建极廉价。
  • 同步靠锁和条件变量，死锁靠加锁顺序规避。
  • CFS 按虚拟时间公平分配 CPU。
