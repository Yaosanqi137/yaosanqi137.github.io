HTTP/1.1 到 HTTP/3 的演进

2026-09-12 · 网络 · 9 分钟

HTTP 协议每次大版本升级，本质都在解决同一个问题：如何减少网络往返、提高带宽利用率。从 1.0 到 1.1，到 2，再到 3，目标从未改变。

HTTP/1.0：每请求一连接

每次请求都建立一条 TCP 连接，用完即断。TLS 握手 + TCP 三次握手，开销巨大。

HTTP/1.1：持久连接 + 管线化

1.1 引入持久连接：默认 Connection: keep-alive，一条 TCP 复用多个请求。管线化（pipelining）理论上允许连续发请求不等响应，但因队头阻塞，实践中很少启用。

GET /index.html HTTP/1.1
Host: www.example.com
Connection: keep-alive

HTTP/2：多路复用

HTTP/2 基于二进制分帧，在一条 TCP 连接上并发多个请求，彻底消除 1.1 的管线队头阻塞。

  • 头部压缩（HPACK）。
  • 服务器推送。
  • 流优先级。

但 HTTP/2 跑在 TCP 上，TCP 层面的丢包仍会导致整条连接队头阻塞。

HTTP/3：QUIC + UDP

HTTP/3 把传输层换成 QUIC：基于 UDP，自带可靠传输、加密、多路复用。每个流独立，丢包只影响对应流，无队头阻塞。

HTTP/3 的核心：用 QUIC 取代 TCP+TLS，把握手从 1-RTT 降到 0-RTT。

对比一览

版本传输多路复用队头阻塞
1.0每请求一 TCP无有
1.1持久 TCP管线（弱）有
2TCP + TLS有TCP 层有
3QUIC + TLS1.3有无

小结

  • 1.1 解决“连接开销”。
  • 2 解决“同连接并发”。
  • 3 解决“丢包队头阻塞 + 握手延迟”。
  • 协议演进主线：把更多逻辑下沉到传输层。
